Magic Mouse battery percentage on Windows 11

To see Magic Mouse battery percentage on Windows 11, use the free Magic Tray (Windows app): it puts the percentage next to the Windows clock. Neither driver in this repo reads battery itself, and how Magic Tray gets the number depends on which route you installed — with the KMDF driver it reads HID Input report 0x90 on collection COL02 directly, and on the Apple-driver route it performs a brief, temporary Mode A to Mode B flip on the device and then flips it back. The drivers’ job is keeping scroll alive on PID 0323.

Does the Magic Mouse v3 Windows driver show battery percentage?

No. Both routes in this repo are kernel-mode lower filters and neither reads or reports battery level. Anything that claims otherwise about this repo is wrong. Reading the battery is userspace work, and it is done by the Magic Tray app.

How do I check Magic Mouse battery on Windows?

Install Magic Tray (Windows app) and look next to the Windows clock. Magic Tray detects which of three states the machine is in — no fix installed, the Apple-driver route, or the KMDF driver — and reports whether pointer, scroll and battery are working in each. Source: the Magic Tray (Windows app) repo on GitHub.

Magic Tray is Windows software — a system-tray utility for Apple mice on Windows. It is not a desk accessory, a keyboard stand, or a 3D-printed or wooden tray, despite what a shopping search suggests.

How the battery read differs between the two routes

Where the battery percentage comes from on each route
RouteHow Magic Tray reads the charge
KMDF driver (v2-kmdf-driver/, PID 0x0323) Straight from HID Input report 0x90 on collection COL02. No mode flip is needed, because the collection carrying the report stays exposed.
Apple-driver route (v1-binary-patch/) Magic Tray flips the device briefly from Mode A to Mode B, takes the reading, and flips it back. The flip is temporary by design.
Magic Mouse v1 0x030D, v2 0x0269 and v2-alt 0x0310 Not yet characterised. Those models use different HID descriptor structures from the 2024 mouse, so the collection that carries report 0x90 on 0x0323 has not been mapped on them and this site makes no claim either way — see issue 22.

Why does Windows 11 not show the battery level itself?

Because the paths Windows normally uses are not dependable for this mouse. Windows Settings and WMI are not reliable sources for Magic Mouse 2024 battery state, and Feature report 0x47 is not where the level lives. The number is in an Input report the mouse sends on a specific collection, so something has to be listening on that collection and decoding it — which is what Magic Tray does.

Why does the scroll driver matter for a battery read?

Because the battery report arrives on a HID collection, and this mouse can lose its collections. After a Bluetooth idle disconnect, DeviceSetupManager property synchronization can collapse the mouse’s HID collections — Mode A → Mode B — leaving a plain mouse with a working cursor and no touch surface. When the collection layout collapses, the collection carrying report 0x90 is not there to read either, so a battery reading can go stale or stop along with scroll.

Does this work on Magic Mouse 1 or Magic Mouse 2?

Scroll, yes: v1 (0x030D), v2 (0x0269) and v2-alt (0x0310) are supported by the Apple-driver route. Battery on those models is a different story and this project does not claim it either way yet: they use different HID descriptor structures from the 2024 mouse, so the collection that carries report 0x90 on 0x0323 has not been mapped on them and the battery path is not yet characterised — issue 22 tracks it.
