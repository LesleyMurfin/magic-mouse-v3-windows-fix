Magic Mouse v3 Windows driver FAQ

Short answers about the Magic Mouse 2024 (v3) Windows driver: Apple never shipped a Windows driver for this mouse, PID 0323 is absent from Boot Camp, and scroll dies on Windows 11 when a Bluetooth idle disconnect collapses the HID collections. This project now offers two fixes, and you install one: the Apple-driver route needs no Test Mode and covers v1, v2 and v3, while the self-signed KMDF driver covers PID 0323 and does require Test Mode. Both are free and MIT licensed.

Install guide Fix dead scroll

Is there an official Apple Windows driver for the 2024 Magic Mouse?

No. Apple never shipped a Windows driver for the 2024 Magic Mouse, and its Bluetooth PID 0323 does not appear in Apple’s Boot Camp INF. That is why this project exists: an independent, MIT-licensed Magic Mouse 2024 (v3) Windows driver.

Which of the two fixes should I install?

This repo ships two independent drivers, and you install one, not both — they attach to the same Bluetooth HID stack. The Apple-driver route (v1-binary-patch/) is the least system change: it registers Apple’s own unmodified signed driver, needs no Windows Test Mode, supports 0x030D, 0x0269, 0x0310 and 0x0323, and its Mac-style scroll sensitivity is fixed. The KMDF driver (v2-kmdf-driver/) supports 0x0323 only and requires Test Mode, but its scroll sensitivity is tunable, it re-arms automatically after a Bluetooth reconnect and after a reboot, and battery is read without a mode flip. Full side-by-side: which route should I install.

Does Boot Camp work with the Magic Mouse 2024 (v3)?

No. The Boot Camp INF has no 0323 entry, so Windows never binds Apple’s driver to the 2024 Magic Mouse. Boot Camp is not a working answer on the older models either: Apple’s installer refuses to run on non-Apple hardware, and even with applewirelessmouse.sys present on disk, Windows will not attach it until something registers it as a lower filter on the device. That registration is what the Apple-driver route here does.

Why does Magic Mouse scroll stop working on Windows 11?

After a Bluetooth idle disconnect, DeviceSetupManager property synchronization can collapse the mouse’s HID collections, Mode A to Mode B. The cursor keeps working and scroll dies, and it does not recover on its own. Full explanation: Magic Mouse 2024 (v3) scroll not working on Windows 11.

Is the Magic Mouse 2024 the same as Magic Mouse 2?

No. Magic Mouse 2 is the Lightning model, PID 0x0269. The 2024 Magic Mouse has USB-C and reports PID 0x0323, and the KMDF driver here targets 0x0323 only. Apple sells both as “Magic Mouse”, which is why this project uses the label v3.

How do I know if I have a Magic Mouse v3?

Check the Hardware Ids: Device Manager → Human Interface Devices → Apple Magic Mouse → Properties → Details → Hardware Ids. PID_0323 means v3, and the charge port is USB-C. PID_030D is v1, PID_0269 is v2, and PID_0310 is the v2-alt identifier. All four are supported by the Apple-driver route.

Do I need Windows Test Mode?

Only for the KMDF driver. That package is self-signed, so Windows loads it only with test signing enabled and Secure Boot and memory integrity off. An EV certificate plus Microsoft attestation signing is the goal, funded off GitHub via Stripe — see the signing and funding page and what Test Mode actually means.

The Apple-driver route needs no Test Mode and lets Secure Boot and memory integrity stay on, because it ships Apple’s own signed binary unmodified and installs no catalog. That is what the signature chain implies and it is the intended configuration, but it has not yet been confirmed on a machine with test signing switched off — the development PC runs with test signing on for the KMDF driver. That check is tracked as issue 20.

Is the Magic Mouse v3 Windows driver free?

Yes. It is free and MIT licensed, with no subscription. It is maintained by Revive Business Solutions / Lesley Murfin, and the whole source tree is on GitHub.

Is this the same as Magic Utilities?

No. Magic Utilities is separate paid software sold on subscription. This project is free and MIT licensed, aimed at the Magic Mouse scroll bug on Windows, and the battery percentage side is handled by the free Magic Tray (Windows app).

Does the driver fix the battery percentage on Windows?

Neither driver reads battery itself — the free Magic Tray (Windows app) does, and how it reads depends on the route. With the KMDF driver it reads HID Input report 0x90 on collection COL02 directly. On the Apple-driver route it performs a brief, temporary Mode A to Mode B flip on the device and then flips it back. Either way the percentage appears next to the Windows clock. Battery on Magic Mouse v1 0x030D, v2 0x0269 and v2-alt 0x0310 is not yet characterised, because those models use different HID descriptor structures and the collection that carries report 0x90 on 0x0323 has not been mapped on them — see issue 22. More detail: Magic Mouse battery percentage on Windows 11.

Does it support Magic Mouse v1 or v2?

Yes, through the Apple-driver route. The KMDF driver is PID 0x0323 only, but the Apple-driver installer in v1-binary-patch/ supports v1 0x030D, v2 0x0269, v2-alt 0x0310 and v3 0x0323 — and it was verified on a real paired v1 sitting alongside a v3 on the same PC.

Installing Apple’s Boot Camp software on its own does not fix those mice. Apple’s installer refuses to run on non-Apple hardware, and even when applewirelessmouse.sys is present Windows never binds the filter until something registers it — which is exactly what this project’s installer does, and the approach sbagirici proved on v1 and v2. The PID lookup table spells out which route you need.

Does it work on Windows 10?

Yes, on Windows 10 build 14393 or later, x64 only. Windows 11 is supported on any build. There is no 32-bit or Arm package.

Does the Magic Mouse work over the USB-C cable on Windows?

The USB-C port on the underside is for charging. The mouse connects for input over Bluetooth, and both routes target that Bluetooth HID path, so plugging in the cable is not a workaround for dead scroll.

How do I uninstall the driver?

For the Apple-driver route, run installer\Uninstall-MagicMousePatch.ps1 as administrator: it removes applewirelessmouse from LowerFilters, deletes the service key, restores the backed-up driver, and prompts for a reboot. For the KMDF driver, find the published INF with pnputil /enum-drivers, remove it with pnputil /delete-driver, or uninstall the device in Device Manager and delete its driver software, then turn Test Mode off and reboot. Step by step: Apple-route rollback and KMDF rollback.

Where is the source code?

On GitHub at github.com/LesleyMurfin/magic-mouse-v3-windows-fix, MIT licensed. The Apple-driver route lives in v1-binary-patch/ and the KMDF driver in v2-kmdf-driver/.
