Magic Mouse 2024 (v3) Windows driver — scroll fix for PID 0323

Apple ships no Windows driver for the 2024 USB-C Magic Mouse, Bluetooth PID 0323. This free, MIT-licensed driver brings two-finger scroll back on Windows 10 and Windows 11. It registers Apple’s own signed driver, so no Test Mode, and it covers Magic Mouse v1, v2, v2-alt and v3.

Install it in three steps

  1. 1

    Turn off Fast Startup

    From an elevated prompt: powercfg /h off, then reboot.

  2. 2

    Download the project, then run the installer

    Download the project repository from GitHub, then double-click v1-binary-patch/Install.cmd. It asks for Administrator itself.

  3. 3

    Reboot

    Two-finger scroll comes back.

Those steps are the Apple-driver route, and it is the only one you can install today. The separate KMDF driver for the 2024 mouse is not finished: there is no compiled driver, no signed package and no installer for it yet. If you find KMDF instructions anywhere, do not follow them until a complete package is published here.

What the installer changes, and what it does not require

The installer copies Apple’s unmodified applewirelessmouse.sys to System32\drivers, creates an applewirelessmouse kernel service, adds that driver to the Bluetooth HID device’s LowerFilters, then restarts the device so Windows re-enumerates it with the filter attached. It uses the bundled unmodified Apple driver, needs no PowerShell window or execution-policy change, and installs no catalog — so no Windows Test Mode is required and Secure Boot and memory integrity can stay on. Scroll feel is Apple’s own Mac-style translation, sensitivity fixed.

The KMDF driver is a separate design for PID 0x0323 only, planned with Test Mode, tunable scroll and automatic recovery. It is unfinished: v2-kmdf-driver/ holds development notes, and there is no compiled driver, no signed package and no installer. Signing is the one thing money would buy for it: an EV certificate plus Microsoft attestation signing would be needed before a production package could load normally.

Why scroll stops

A Bluetooth idle disconnect makes Windows collapse the mouse’s HID collections, and the touch-surface collection COL02 disappears. Clicks and cursor movement keep working, so the mouse looks healthy. It does not recover on its own. Symptom walkthrough: Magic Mouse scroll not working on Windows 11.

Mode A to Mode B, and why DSM does not self-recover

DeviceSetupManager (DSM) runs a property synchronisation pass on reconnect, and the device can come back in this reduced form. Before this driver, the only ways back were a driver reinstall or re-pairing the mouse.

Battery percentage

The driver does not read battery. The Magic Tray app does, from HID input report 0x90 on COL02. It briefly removes applewirelessmouse from the mouse’s LowerFilters to expose that collection, reads the percentage, then restores the filter — two-finger scroll is unavailable for the few seconds that takes. Why Boot Camp does not fix it either

Apple’s Boot Camp package has no entry for PID 0323, so Windows falls back to its generic HID mouse stack. Boot Camp does not rescue the older mice either: Apple’s installer refuses to run on non-Apple hardware, and even when applewirelessmouse.sys is present on disk, Windows will not attach it to the mouse until something registers the driver as a lower filter on the device. That registration is exactly what this project’s installer does — the approach sbagirici proved on Magic Mouse v1 and v2.
