Magic Mouse 2024 (v3) Windows driver — scroll fix for PID 0323

Apple ships no Windows driver for the 2024 USB-C Magic Mouse, Bluetooth PID 0323 — that ID is absent from the Boot Camp INF. This project is a free, MIT-licensed fix for two-finger scroll on Windows 10 and Windows 11. The shipped Apple-driver route registers Apple’s own unmodified signed driver, needs no Windows Test Mode, and works on v1, v2, v2-alt and v3. The KMDF route is development documentation only on this branch and has no installable package. The Magic Tray (Windows app) shows battery percentage in the tray.

Does Apple make a Windows driver for the 2024 Magic Mouse?

No. Apple's Boot Camp driver package contains no entry for PID 0323, so Windows loads only its generic HID mouse stack for the 2024 Magic Mouse. Clicking and cursor movement work out of the box, but nothing from Apple teaches Windows how to keep the touch-surface scroll collection alive.

Installing Apple's Boot Camp software does not rescue the older mice either: Apple's installer refuses to run on non-Apple hardware, and even when applewirelessmouse.sys is present on disk, Windows will not attach it to the mouse until something registers the driver as a lower filter on the device. That registration is exactly what this project's Apple-driver installer does — the approach sbagirici proved on Magic Mouse v1 and v2.

Why does Magic Mouse scroll stop working on Windows 11 after a Bluetooth reconnect?

Because Windows collapses the mouse's HID collections. After a Bluetooth idle disconnect, DeviceSetupManager (DSM) runs a property synchronisation pass, and on reconnect the device can come back in a reduced form — this project calls it Mode A → Mode B. Mode A exposes the full collection set including the touch-surface report; Mode B exposes only the plain mouse collection. The cursor still moves and clicks still register, so the mouse looks healthy, but two-finger scroll is gone. It does not self-recover: before this driver, the only ways back were a driver reinstall or re-pairing the mouse.

What does the Magic Mouse v3 Windows driver do?

The shipped Apple-driver route is a kernel-mode lower filter on the mouse's Bluetooth HID stack. The KMDF route is development work only on this branch, so it has no installable user path here.

  • Apple-driver route (v1-binary-patch/, v1.0.0, production ready) — ships Apple's own applewirelessmouse.sys completely unmodified and registers it: the binary is copied to System32\drivers, an applewirelessmouse kernel service is created, the driver is added to the device's LowerFilters, and the Bluetooth HID device is restarted. Because the binary is untouched and no catalog is installed, no Windows Test Mode is required. Scroll feel is Apple's own Mac-style translation, and sensitivity is fixed. Supports 0x030D, 0x0269, 0x0310 and 0x0323.
  • KMDF route (v2-kmdf-driver/) — development documentation only. No compiled .sys, installable package, or installer ships on this branch. Planned scope is PID 0x0323 with Test Mode, tunable scroll and automatic recovery; these are not current install options.

Install the shipped Apple-driver route. Do not combine it with unreleased KMDF work.

Which Magic Mouse do I have?

Check the Bluetooth product ID: in Windows, open Device Manager → Human Interface Devices → Apple Magic Mouse → Properties → Details → Hardware Ids, and read the PID_ value. The shipped Apple-driver route supports all four mouse PIDs; the unreleased KMDF work is not available from this branch.

How do I see Magic Mouse battery percentage on Windows?

Use the Magic Tray app — the shipped Apple-driver route does not read battery itself. The 2024 Magic Mouse reports its charge on HID Input report 0x90, collection COL02, and Magic Tray reads it in userspace with a brief, temporary Mode A to Mode B flip on the device and then flips it back. The unreleased KMDF route is not available from this branch.

How do I install the Magic Mouse 2024 (v3) Windows driver?

For the shipped Apple-driver route, turn Fast Startup off (powercfg /h off from an elevated prompt, then reboot), download the repo and double-click v1-binary-patch/Install.cmd: it asks for Administrator itself, uses the bundled unmodified Apple driver, needs no PowerShell window and no execution-policy change, and a reboot finishes the job. No Test Mode, and Secure Boot and memory integrity can stay on.

The KMDF route is not currently installable. This branch contains development documentation only; no compiled driver, signed package, or installer is shipped here. Do not follow KMDF installation instructions until a complete package is published.

The full sequence for the shipped route, including rollback, is on how to install the Apple-driver route.

Is this driver free, and how does it compare to Magic Utilities?

It is free and MIT licensed, with no subscription. Magic Utilities is paid software sold on a subscription; this project is not, and nothing here expires or stops scrolling when a licence lapses. It is maintained by Revive Business Solutions / Lesley Murfin and is not affiliated with Apple.

Signing is the one thing money buys for the future KMDF route. That route is development work only on this branch; an EV certificate plus Microsoft attestation signing would be needed before a production package could load normally. The Apple-driver route sidesteps the problem because it redistributes Apple's own signed binary without touching a byte of it.
