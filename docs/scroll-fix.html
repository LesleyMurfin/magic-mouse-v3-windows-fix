Magic Mouse 2024 (v3) scroll not working on Windows 11

Cursor still moves, two-finger scroll is dead: Windows collapsed the mouse’s HID collections after a Bluetooth idle disconnect. The shipped Apple-driver route registers Apple’s own unmodified signed driver as a lower filter and needs no Windows Test Mode. The KMDF route is development documentation only and is not shipped on this branch.

Root cause

Why does Magic Mouse scroll stop working on Windows 11?

Windows rebuilds the device with the wrong shape. After a Bluetooth idle disconnect, DeviceSetupManager (DSM) runs a property sync against the cached device state, and the HID collections the mouse exposes get collapsed — this project calls it Mode A → Mode B. Mode A keeps the touch-surface scroll data on its own collection; Mode B merges everything into one plain-mouse collection, which has a cursor and buttons and no scroll surface. Nothing in Windows’ mouse settings can re-expose a collection that no longer exists.

Registry-level detail: DynamicCachedServices

The collapse is visible in HKLM\SYSTEM\CurrentControlSet\Enum\BTHENUM\...\Device Parameters\DynamicCachedServices, a 560-byte binary value (35 × 16-byte entries). In Mode A, entry 0 is COL01 and entry 1 is COL02; after the DSM-triggered rewrite in Mode B, entry 0 is the unified TLC and entry 1 is empty. The exact BTHPORT internal code path from the 35th DSM property write to the descriptor rewrite has not been reverse-engineered — the property write is the confirmed trigger, the collapse mechanism inside BTHPORT is not yet fully characterised.

Full write-up: bug analysis of the DSM and BTHPORT path and the Mode A / Mode B HID collection diagram.

Common bad advice: “just install the Apple driver.” Apple’s Boot Camp INF has no 0323 entry, so there is no Apple entry for the 2024 Magic Mouse to bind to. On v1/v2 it is no better: Apple’s installer refuses to run on non-Apple hardware, and even with applewirelessmouse.sys on disk, Windows will not attach it until something registers it as a lower filter — which is what the Apple-driver route does.

The device stack

Where the collapse happens in the driver stack

The Bluetooth HID path a scroll event travels, from the paired mouse up to your application — and where the shipped fix inserts itself.

  1. 1

    Application

    The foreground app (browser, Explorer, anything) expects a scroll event.

  2. 2

    Input Manager

    Windows translates parsed HID reports into pointer and scroll input.

  3. 3

    hidclass.sys

    The HID class driver interprets the reports coming up the stack.

  4. 4

    HidBth.sys

    HID-over-Bluetooth miniclass driver, parses the collections the mouse reports.

  5. 5

    applewirelessmouse.sys Lower filter — shipped fix

    Apple’s own signed driver, registered here by the Apple-driver installer.

  6. 6

    BTHENUM

    The Bluetooth Enumerator PDO for the paired Magic Mouse.

  7. 7

    BTHPORT Collapse happens here

    Owns DynamicCachedServices; the DSM resync rewrite that merges COL01/COL02 into one TLC happens in this layer.

  8. 8

    Hardware

    The Magic Mouse’s Bluetooth HID radio and firmware.

Try this first

Rule out the cheap causes

Before you install a kernel driver, work through this in order.

  1. 1

    Re-pair the mouse

    Remove it in Bluetooth settings, then pair again. If scroll comes back and dies again after the next idle period, you have this bug.

  2. 2

    Confirm the PID

    Device Manager → Human Interface Devices → Apple Magic Mouse → Properties → Details → Hardware Ids. Look for PID_0323.

  3. 3

    Check which mouse it is

    PID_030D is the 2009 AA-battery mouse, PID_0269 is Magic Mouse 2 (Lightning), PID_0310 is the v2-alt identifier. The shipped route covers all of them.

  4. 4

    Rule out a trackpad

    Magic Trackpads report 030E, 0265, or 0324; the shipped route does not target them.

  5. 5

    Install the shipped fix

    Follow the Apple-driver install guide. No Windows Test Mode, covers v1/v2/v2-alt/v3. The KMDF route is development work only — do not try to install it.

More questions

Will this fix the battery percentage too?

No. The shipped Apple-driver route restores scroll but does not read battery. The free Magic Tray (Windows app) shows battery percentage with a brief temporary mode flip. The KMDF route is not shipped on this branch. Details, including why v1/v2 battery is not yet characterised: Magic Mouse battery percentage on Windows 11.

Is this a battery or Bluetooth range problem?

No, and it is not a Windows setting you can toggle either. It is a one-way HID collection collapse triggered by a DeviceSetupManager resync. Nothing in the Windows mouse settings can re-expose a collection that no longer exists — only re-pairing, a driver reinstall, or the shipped lower filter restore it.
