How to install the Magic Mouse 2024 (v3) Windows driver

There are now two ways to restore two-finger scroll, and you install one of them, not both. The Apple-driver route is a double-click on Install.cmd: it registers Apple’s own unmodified signed driver, needs no Windows Test Mode, and works on Magic Mouse v1, v2, v2-alt and the 2024 model. The KMDF route is this project’s own filter driver for PID 0323: tunable scroll, automatic recovery, and it does require Test Mode because it is self-signed. Both are free, MIT licensed, and run on Windows 10 (build 14393 or later) and Windows 11 x64.

Which route should I install?

Both routes are kernel-mode lower filters that attach to the same Bluetooth HID stack, so installing both is not a supported configuration. Pick the row that matters most to you.

Install one route, not both. If you already have one installed, roll it back before installing the other — see Apple-route rollback or KMDF rollback.

Route 1: the Apple-driver route (no Test Mode)

Package to install
v1-binary-patch — Apple’s applewirelessmouse.sys, unmodified. Installer: Install.cmd.
Devices
Magic Mouse v1 0x030D, v2 0x0269, v2-alt 0x0310, and the 2024 model (v3) 0x0323.
Signing
Apple’s binary is untouched and no catalog is installed, so no Windows Test Mode is required and Secure Boot and memory integrity can stay on.
Reboots
Two if Fast Startup is on: one after powercfg /h off, one after the installer. One if Fast Startup is already off.
Scroll
Apple’s own Mac-style translation. Sensitivity is fixed, not tunable.

This route is not a patch and it does not modify anything Apple shipped. The fix is registration: copy the .sys to System32\drivers, create the applewirelessmouse kernel service, add applewirelessmouse to the device’s LowerFilters, and restart the Bluetooth HID device. Installing Apple’s Boot Camp software on its own does not give you scroll: Apple’s installer refuses to run on non-Apple hardware, and even with the file present Windows will not attach the filter until something registers it. This is the approach sbagirici proved on Magic Mouse v1 and v2.

Before you start: turn Fast Startup off, or the installer refuses to run. From an elevated prompt run powercfg /h off, then reboot. Fast Startup is on by default on Windows, and with it on the driver registration silently fails to take effect.

Apple-route install steps

  1. Check which Magic Mouse you have. Device Manager → Human Interface Devices → Apple Magic Mouse → Properties → Details → Hardware Ids. This route supports PID_030D, PID_0269, PID_0310 and PID_0323.
  2. Download the repo and verify the bundled Apple driver. Get the magic-mouse-v3-windows-fix repository on GitHub. The bundled applewirelessmouse.sys is Apple’s own binary, byte for byte: SHA256 08F33D7E3ECE2C73950A9706F1C4C9057894EAEAF1C4FB355F261F3C2333378F, 78,424 bytes, file version 6.1.7700.0, Authenticode signature Valid, signer CN=Microsoft Windows Hardware Compatibility Publisher. Check it with Get-FileHash -Algorithm SHA256 applewirelessmouse.sys and Get-AuthenticodeSignature applewirelessmouse.sys.
  3. Double-click Install.cmd. In v1-binary-patch\, double-click Install.cmd. It asks for Administrator itself, uses the bundled Apple driver, and needs no PowerShell window and no execution-policy change. It does the registration described above.
  4. Reboot and test two-finger scroll. Reboot to finish, then swipe two fingers on the glass. If you later unpair and re-pair the mouse, run Install.cmd again — the filter is registered against the device InstanceId, and re-pairing can change it. If you want to know why scroll broke in the first place, read why Magic Mouse scroll stops working on Windows 11.
  5. Uninstall or roll back. Run installer\Uninstall-MagicMousePatch.ps1 as administrator. It stops the applewirelessmouse service, restores the backed-up driver, removes applewirelessmouse from LowerFilters, deletes the service registry key, re-enables the device, and prompts for a reboot.

Advanced: the PowerShell installer

Install.cmd is a wrapper. If you would rather drive it directly, run installer\Install-MagicMousePatch.ps1 as administrator. Useful switches:

  • -DriverPath — use a specific applewirelessmouse.sys instead of the bundled one.
  • -FromDriverStore — take the driver from the Windows driver store.
  • -TargetPid <030D|0310|0269|0323> — register against a specific Magic Mouse model.
  • -DryRun — report what would happen and change nothing.

The installer identifies which binary it was handed from the Authenticode signature. A binary whose signature does not verify — patched but never re-signed, or a corrupted download — is refused. A legacy byte-patched and re-signed variant (SHA256 370A5555…, signed with this project’s own MagicMouseFix certificate) is no longer shipped; it is documented only so an existing install can be identified, and that variant does require Test Mode.

Route 2: the KMDF driver (PID 0323, Test Mode required)

Device
Apple Magic Mouse 2024 (USB-C), called Magic Mouse v3 in this project. Bluetooth VID 05AC, PID 0x0323. This route does not support v1, v2 or v2-alt.
Package to install
v2-kmdf-driver — a KMDF filter driver, version 2.0.4.3. Installer: Setup-Community.cmd, which signs the package locally before installing it.
OS support
Windows 10 build 14393 or later, and Windows 11 any build. x64 only.
Signing
Self-signed, so Test Mode is required for this route. EV certificate plus Microsoft attestation signing is the goal.
Price and licence
Free, no subscription. MIT licence.
What it fixes
Generates two-finger scroll directly from the touch surface as HID Wheel and AC Pan, and re-arms it after a Bluetooth reconnect or a reboot.

What do I need before I install the KMDF driver?

  • Windows 10 build 14393 or later, or Windows 11, x64.
  • An administrator account — this is a kernel-mode driver.
  • The mouse paired over Bluetooth and reporting PID_0323.
  • Secure Boot off and memory integrity off, otherwise Windows ignores the Test Mode setting.
  • Two reboots — one to enter Test Mode, one after the driver installs.

KMDF install steps

  1. Confirm your mouse reports PID 0323. Open Device Manager → Human Interface Devices → Apple Magic Mouse → Properties → Details → Hardware Ids, and look for PID_0323. If you see PID_030D, PID_0269 or PID_0310 you have a v1, v2 or v2-alt mouse; the KMDF driver will not bind to it, so use the Apple-driver route instead.
  2. Download the driver package from the GitHub repo. Get the v2-kmdf-driver package from the magic-mouse-v3-windows-fix repository on GitHub. This is the package the Magic Tray (Windows app) installs. It installs as its own driver package alongside Apple’s and never overwrites MagicMouseDriver.sys.
  3. Verify the SHA256 hash of the download. In PowerShell, run Get-FileHash -Algorithm SHA256 <file> and compare the result with the hash published in v2-kmdf-driver/FREEZE-HASH.md. Do not install a kernel driver whose hash does not match.
  4. Enable Windows Test Mode. This step belongs to the KMDF route only. The KMDF driver is self-signed, so Windows must be willing to load test-signed kernel code. From an elevated prompt: bcdedit /set testsigning on, then reboot. Secure Boot and memory integrity must be off, or Windows ignores the setting. See what Test Mode actually means below.
  5. Sign the package locally and install it. Run Setup-Community.cmd from the v2-kmdf-driver folder as administrator. No compiled .sys ships on GitHub, so the script generates a local code-signing certificate (CN=MagicMouseDriver Community, the private key never leaves your PC), trusts it, signs the package, and runs pnputil /add-driver. Install-KMDF.cmd is the pnputil-only step for a package that is already signed. The Magic Tray (Windows app) repo ships the same action, so you can let Magic Tray do this for you instead of running the script by hand.
  6. Reboot and verify scroll survives a Bluetooth disconnect. Reboot. Then leave the mouse alone until Windows drops the Bluetooth link, wake it, and check two-finger scroll. That idle-then-reconnect cycle is the exact condition that used to kill the wheel, so it is the only test that matters. Two fingers on the glass scroll; one finger resting or dragging correctly does not. Background: why Magic Mouse scroll stops working on Windows 11.
  7. Tune the scroll sensitivity. This route’s scroll step is a registry value, ScrollStep, default 8, where higher means less sensitive. Change it with scripts\mm-scroll-tune.ps1 -ScrollStep N. It takes effect on a device restart — no rebuild, no re-sign, no reinstall.
  8. Uninstall or roll back. List installed packages with pnputil /enum-drivers, find the entry for this driver, and remove it with pnputil /delete-driver <oemN.inf> /uninstall. You can also uninstall the device under Human Interface Devices in Device Manager and tick the option to delete the driver software. Then turn Test Mode off with bcdedit /set testsigning off and reboot.

The KMDF driver re-arms multitouch automatically after a Bluetooth reconnect and after a reboot, using a scheduled task named MmAutoF1Watcher. The reboot-recovery path is verified at install time; confirmation across a real reboot is still tracked as issue 25, and community testing on a second PC is wanted — see issue 24.

What does Test Mode actually mean?

Test Mode applies to the KMDF route only. It tells Windows to load kernel drivers that are signed with a certificate Windows does not trust by default. Nothing else about the machine changes, but Windows shows a watermark in the desktop corner, Secure Boot and memory integrity have to stay off, and some anti-cheat and enterprise policies refuse to run while test signing is on. Turning it off is one command and a reboot.

For the KMDF driver this is a funding problem, not a design choice. Kernel drivers need an EV code-signing certificate and Microsoft attestation signing, renewed annually, before Windows will load them normally, and that is the stated goal for this driver — see the signing and funding page and issue 23.

The Apple-driver route avoids the question entirely: it redistributes Apple’s own signed binary without altering a byte and installs no catalog, so it needs no Test Mode and Secure Boot and memory integrity can stay on. That is what the signature chain implies and it is the intended configuration, but it has not yet been confirmed on a machine with test signing switched off — the development PC has test signing enabled for the KMDF driver. That verification is tracked as issue 20.

Do not disable driver signature enforcement on a machine you do not control, and do not install kernel drivers you have not hash-checked.
