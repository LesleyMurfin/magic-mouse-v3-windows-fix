How to install the Magic Mouse 2024 (v3) Windows driver

This page installs the shipped Apple-driver route: double-click Install.cmd to register Apple’s own unmodified signed driver, with no Windows Test Mode, on Magic Mouse v1, v2, v2-alt and the 2024 model. The KMDF route is development documentation only; this branch contains no installable package, compiled driver or installer for it. Both routes must not be combined.

Route 1: the Apple-driver route (no Test Mode)

This route is not a patch: it does not modify anything Apple shipped. The fix is registration — copying Apple’s .sys into System32\drivers, creating the applewirelessmouse kernel service, adding it to the device’s LowerFilters, and restarting the Bluetooth HID device. This is the approach sbagirici proved on Magic Mouse v1 and v2.

Why doesn’t Apple’s Boot Camp installer just work?

Installing Apple’s Boot Camp software on its own does not give you scroll: Apple’s installer refuses to run on non-Apple hardware, and even with the file present Windows will not attach the filter until something registers it.

Signing and Test Mode

Apple’s binary is untouched and no catalog is installed, so no Windows Test Mode is required and Secure Boot and memory integrity can stay on.

Reboots required

Two if Fast Startup is on: one after powercfg /h off, one after the installer. One if Fast Startup is already off.

Scroll feel

Apple’s own Mac-style translation. Sensitivity is fixed, not tunable.

Before you start: turn Fast Startup off, or the installer refuses to run. From an elevated prompt run powercfg /h off, then reboot. Fast Startup is on by default on Windows, and with it on the driver registration silently fails to take effect.

Apple-route install steps

  1. 1

    Check which mouse you have

    Device Manager → Human Interface Devices → Apple Magic Mouse → Properties → Details → Hardware Ids. This route covers PID_030D, PID_0269, PID_0310 and PID_0323.

  2. 2

    Download and verify the driver

    Get the magic-mouse-v3-windows-fix repository on GitHub. The bundled applewirelessmouse.sys is Apple’s own binary, byte for byte.

    Hash, version and signer to verify

    SHA256 08F33D7E3ECE2C73950A9706F1C4C9057894EAEAF1C4FB355F261F3C2333378F, 78,424 bytes, file version 6.1.7700.0, Authenticode signature Valid, signer CN=Microsoft Windows Hardware Compatibility Publisher. Check it with Get-FileHash -Algorithm SHA256 applewirelessmouse.sys and Get-AuthenticodeSignature applewirelessmouse.sys.

  3. 3

    Double-click Install.cmd

    In v1-binary-patch\, double-click Install.cmd. It asks for Administrator itself — no PowerShell window, no execution-policy change — and performs the registration above.

  4. 4

    Reboot and test two-finger scroll

    Reboot to finish, then swipe two fingers on the glass. Unpairing and re-pairing changes the device InstanceId — run Install.cmd again if scroll stops. See why Magic Mouse scroll stops working on Windows 11.

  5. 5

    Uninstall or roll back

    Run installer\Uninstall-MagicMousePatch.ps1 as administrator to restore the backed-up driver and remove the filter.

    Exactly what rollback does

    It stops the applewirelessmouse service, restores the backed-up driver, removes applewirelessmouse from LowerFilters, deletes the service registry key, re-enables the device, and prompts for a reboot.

Advanced: the PowerShell installer

Install.cmd is a wrapper. To drive it directly, run installer\Install-MagicMousePatch.ps1 as administrator with any of these switches:

PowerShell installer switches
SwitchEffect
-DriverPathUse a specific applewirelessmouse.sys instead of the bundled one.
-FromDriverStoreTake the driver from the Windows driver store.
-TargetPid <030D|0310|0269|0323>Register against a specific Magic Mouse model.
-DryRunReport what would happen and change nothing.
Signature verification and the legacy signed variant

The installer identifies which binary it was handed from the Authenticode signature. A binary whose signature does not verify — patched but never re-signed, or a corrupted download — is refused. A legacy byte-patched and re-signed variant (SHA256 370A5555…, signed with this project’s own MagicMouseFix certificate) is no longer shipped; it is documented only so an existing install can be identified, and that variant does require Test Mode.

What does Test Mode mean for this project?

Test Mode is relevant only to the unreleased KMDF development work. It tells Windows to load kernel drivers signed with a certificate Windows does not trust by default, and normally requires Secure Boot and memory integrity to be off. The shipped Apple-driver route uses Apple’s own signed binary without altering a byte and installs no catalog, so it needs no Test Mode.

Do not enable Test Mode to install the shipped Apple-driver route. Do not disable driver signature enforcement on a machine you do not control, and do not install kernel drivers you have not hash-checked.
